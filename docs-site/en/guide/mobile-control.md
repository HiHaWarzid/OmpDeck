# Mobile Control

OmpDeck can be controlled from a phone browser: browse session history, reopen historical sessions, create new sessions, and keep chatting. The phone uses a dedicated lightweight page instead of loading the 4 MB desktop renderer bundle; it reuses the built-in web service and the same pi sessions — no app install and no third-party relay required.

## What You Can Do

- Browse sessions per project and reopen historical sessions.
- Create sessions, send prompts, and stop the current turn (aborts generation without closing the session).
- Attach up to four photos (auto-compressed); while the agent is running, choose **steer into current turn** or **queue for next turn**.
- Switch models and thinking levels.
- Tool calls are grouped by turn; tap one for full arguments and results.
- Load earlier messages on demand in long conversations.

Agent confirmation/selection requests still belong on the desktop. If a project has not been trusted yet, creating or resuming a session from the phone shows a trust prompt where you can trust for this run, always trust, or deny.

Mobile control focuses on chat and session control; the lightweight page is currently Chinese-only. Desktop-only surfaces — terminal, file tree/editor, Git panel, settings/Skills/Extensions, session import/export/rename/delete, and project management — still belong on the desktop app.

## Enable It

1. On the desktop app, open **Settings → Web Service**.
2. Turn the service on.
3. Choose the listen address:
   - **Loopback only (127.0.0.1)** — default; only this computer can connect.
   - **LAN (0.0.0.0)** — allow phones on the same network. This must be selected explicitly.
4. Confirm the port (default `8765`) and allow it through the system firewall if needed.
5. Connect the phone to the same network, then scan the QR code on the settings page or open the copied token URL in the phone browser.

After the first visit, the token is stored in that browser's local storage and the `?token=` query is removed from the address bar. Later visits can use the site URL directly.

## Remote / Off-network Access (Built-in Tailscale)

If you do not want to manage port forwarding, use the built-in Tailscale Serve integration:

1. Install Tailscale on the computer and the phone, and sign both into the same tailnet.
2. Open **Settings → General → Phone Remote Access (Tailscale)** on the desktop and turn on the switch. OmpDeck turns on the web service and runs `tailscale serve --bg --yes --https=8443 http://127.0.0.1:<port>`.
3. The first use requires enabling **HTTPS certificates / Serve** in the Tailscale admin console. The settings page reports a retryable error until it is enabled; activation usually takes a few seconds.
4. Once the state becomes “connected”, the settings page shows `https://<machine>.<tailnet>.ts.net:8443` and a QR code; scan it on the phone.
5. Disabling remote access or quitting OmpDeck removes only the Serve rule pointing at its own local port; other Serve rules are untouched.

Tailscale handles network encryption and device authentication; the OmpDeck access token is still required. Requests proxied through Serve are never treated as local loopback traffic, even though Serve connects back from `127.0.0.1`.

## Access Token

- Non-loopback requests (phone, another computer, tunnel hostname) must carry the token; only loopback Hosts such as `127.0.0.1`, `localhost`, and `::1` are exempt.
- The token is generated by the main process. The default lifetime is **30 days**; the settings page offers 1 day, 7 days, 30 days, or never expires.
- **Rotating the token** immediately disconnects every phone holding the old token; scan again afterwards.
- If a phone is lost or the token leaks, rotate the token first, then disable the web service if necessary.
- Do not post token-bearing QR codes, links, or screenshots publicly.

## Security Guidance

- The default listener is `127.0.0.1`. Switch to `0.0.0.0` only when phone access is actually needed.
- Plain LAN HTTP is not encrypted: the token and conversation content cross Wi-Fi in clear text. This is acceptable on a trusted home/office network, but not recommended on public Wi-Fi.
- For remote access or HTTPS, prefer a private network or tunnel such as **Tailscale Serve** or **Cloudflare Tunnel**, terminate TLS at that entry point, and keep token auth enabled.
- Never map port `8765` directly to the public internet.
- The web service has a single token, with no multi-user accounts, roles, or per-device revocation. Treat it as a personal remote entry to your development machine, not a shared team service.

## Install as a PWA

In a secure context (HTTPS or `localhost`), OmpDeck can be added to the phone home screen:

- **iOS Safari**: Share → Add to Home Screen.
- **Android Chrome**: Menu → Install app / Add to Home screen.

The service worker precaches the app shell, uses network-first for navigation and cache-first for hashed assets; `/api/` session data is never cached. Message polling requests only the latest window plus collapsed previews, and expands full content by message id on demand; the refresh rate increases automatically while an agent is running. Plain LAN HTTP usually does not qualify for PWA installation — that is a browser rule, not an app setting.

## Troubleshooting

**The phone cannot open the page**

- Confirm the phone and computer are on the same network without guest-network isolation.
- Confirm the listen address is `0.0.0.0` and use the computer's LAN IP, not `127.0.0.1`.
- Check that the system firewall allows the port.

**Missing / invalid / expired token**

- Scan the latest QR code on the settings page or copy the current URL again.
- Expired or rotated tokens stop working immediately.
- Clearing browser site data also removes the stored token.

**The QR code shows localhost**

The listener is still loopback-only. Switch to LAN; the settings page then generates the QR code from a routable LAN address.

**The PWA cannot be installed**

Use HTTPS, or open it from `localhost` on the same machine. The page still works over plain LAN HTTP, but the browser will not register the service worker.
